Building a Realtime Forum in Go

by the wr docs · 6 min read · 2026

Build a 100% CLI realtime forum in Go: TCP, TLS, deduplicated broadcast and resilient reconnects, zero dependencies. This is the page the recordings in media/ use, so a frame is always the same frame.

Why a reader

Documentation and long articles read better as plain text with real typography than as a wall of markup. wr fetches the page, extracts the article and draws it with the terminal's own colors. See the guide or the QA report.

Getting started

  1. Install it with the installer or go install.
  2. Open an address: wr https://example.com/article.
  3. Type plain words to search the web.

The server

package main

import (
	"bufio"
	"crypto/tls"
	"log"
	"net"
)

func main() {
	cfg := &tls.Config{MinVersion: tls.VersionTLS13}
	ln, err := tls.Listen("tcp", ":8443", cfg)
	if err != nil {
		log.Fatal(err)
	}
	for {
		c, err := ln.Accept()
		if err != nil {
			continue
		}
		go handle(bufio.NewReader(c), c)
	}
}

Every client gets a goroutine and a deduplicated broadcast fan-out; a reconnect resumes from the last acknowledged message.

Reading

  • / searches as you type, n/N jump.
  • t opens the section index; ]/[ move.
  • Drag to select and copy: code keeps its indentation and loses its frame.

Browsing

Links are clickable; press f to label every one on screen and type the hint. Back and forward restore the exact scroll position, and cached pages open instantly.

Shortcuts

KeyAction
oopen an address or search
tsection index
flabel the links on screen
H / Lback / forward

Limits

No JavaScript and no forms: pages that draw their content with JS come out empty or incomplete. Images and PDFs are not shown; press x to open them in the browser.
